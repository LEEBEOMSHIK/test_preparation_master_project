# /next — 다음 작업 발굴 (백로그 디스커버리)

이 스킬은 "지금 뭐가 필요한지/다음에 뭘 하면 좋을지"를 **webapp-planner에게 물어** 프로젝트를 스캔하게 하고, 우선순위가 매겨진 후보 목록을 제시한 뒤, 사용자가 고른 항목을 **`/feature`로 넘긴다**.

`/feature`(주어진 요구사항을 끝까지 구현)와 책임이 다르다. 이 스킬은 **무엇을 만들지 발굴·제안**까지만 하고 직접 구현하지 않는다.

---

## 사용 판단

- **사용함**: "다음에 뭐 하지", "개선점 찾아줘", "할 일 추천", 무엇을 만들지 정하지 못한 상태에서 후보가 필요할 때.
- **사용 안 함**: 이미 만들 기능이 정해진 경우 → 바로 `/feature <요구사항>`. 단순 질문/조회 → 직접 답변.

---

## 진행 절차

### 1단계 — 범위 파악
- args로 포커스 영역을 받는다(예: `/next 사용자 화면`, `/next 백엔드 정합성`). 없으면 **프로젝트 전체**가 범위.
- 범위가 지나치게 모호하면(무엇을 기준으로 추천할지 불명확) 한 가지 핵심 질문으로 좁힌다. 명확하면 바로 2단계.

### 2단계 — 발굴 (webapp-planner)
`Agent`(subagent_type: `webapp-planner`)에 다음을 요청한다. **코드를 작성하지 말고 후보 목록만** 산출하게 한다.

> 프로젝트(코드·`docs/`·`docs/history/`·최근 git 로그·CLAUDE.md/AGENTS.md)를 스캔해 "다음에 할 만한 작업" 후보를 발굴하고 우선순위를 매겨라.

webapp-planner가 각 후보에 대해 산출할 항목:
- **후보명** (한 줄)
- **분류**: 기능 신규 / 버그 / 개선(UX·성능) / 기술부채 / 정합성(미완·누락)
- **근거**: 왜 필요한가 (관찰된 사실 — 예: "FALLBACK_NAV에만 있고 DB 시딩 누락")
- **영향 범위**: FE / BE / DB
- **예상 규모**: S(단일 파일·수정) / M(다층) / L(대규모)
- **우선순위**: High / Med / Low (근거 포함)
- **권장 처리 경로**: `/feature`(다층 기능) vs 직접 수정(사소)

발굴은 추측이 아니라 **코드·문서·이력에서 관찰된 근거**에 기반해야 한다(없는 결함을 지어내지 않는다).

### 3단계 — 제시 & 선택
- webapp-planner가 우선순위순으로 정렬한 후보를 사용자에게 요약 표로 보여준다.
- 상위 후보를 `AskUserQuestion`의 옵션으로 제시한다(옵션은 최대 4개 — 상위 3~4개 후보. 목록에 없는 것은 사용자가 'Other'로 직접 입력 가능).
- 사용자가 하나를 고른다(또는 직접 입력).

### 4단계 — 핸드오프
- 선택 항목이 **다층 기능**이면: "이 항목을 `/feature`로 구현 시작할까요?"를 묻고, 승인 시 **`/feature` 파이프라인으로 그대로 진행**한다(분석→설계→승인→구현→검증→테스트).
- 선택 항목이 **사소한 수정**이면: `/feature` 없이 직접 처리할지 제안한다.
- 사용자가 "지금은 안 함"이면 선택 항목만 기록하고 종료한다.

---

## 이 스킬이 하지 않는 것

- 직접 구현·커밋·push 하지 않는다 (구현은 `/feature` 또는 webapp-developer 단계).
- 근거 없는 작업을 지어내지 않는다 — 반드시 코드·문서·이력에서 관찰된 것만 후보로 올린다.
- 우선순위를 사용자 대신 확정하지 않는다 — 제안할 뿐, 선택은 사용자가 한다.

## 응답 언어

모든 진행 안내·후보 목록은 한국어로 작성한다.
