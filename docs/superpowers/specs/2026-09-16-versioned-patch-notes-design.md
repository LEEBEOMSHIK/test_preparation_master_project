# 버전별 패치노트 설계

## 목표

배포가 완료된 TPMP 버전을 기준으로, 관리자 화면에서 한 버전에 여러 패치 항목을 등록하고 사용자가 버전별 목록으로 확인할 수 있게 한다.

## 사용자 흐름

관리자는 패치노트 등록 화면에서 버전과 릴리즈 제목을 입력한 뒤, 패치 항목을 행 단위로 추가한다. 각 행에는 유형과 한 줄 요약을 입력하고 순서를 조정할 수 있다. 저장 전 게시 여부와 사용자에게 보일 미리보기를 확인한다. 사용자는 게시된 릴리즈만 최신 게시일 순서로 보고, 릴리즈 카드 내부에서 유형별 배지와 항목 요약을 확인한다.

## 데이터 모델

기존 `patch_notes` 테이블과 엔티티는 버전 릴리즈로 유지한다. 다음 `patch_note_items` 테이블을 추가한다.

| 컬럼 | 규칙 |
|---|---|
| `id` | BIGINT 자동 증가 PK |
| `patch_note_id` | `patch_notes.id` FK, 삭제 시 하위 항목도 소프트 삭제 처리 |
| `item_type` | `ADD`, `IMPROVEMENT`, `FIX`, `SECURITY`, `ETC` |
| `summary` | 필수, 최대 200자 |
| `display_order` | 0 이상의 정수 |
| 공통 감사 컬럼 | 프로젝트 `BaseEntity` 규칙 적용 |

기존 릴리즈의 `content`는 하위 항목이 없을 때 `ETC` 항목으로 읽어 보여준다. 기존 컬럼과 기존 API의 호환성을 유지하며, 새 저장 요청은 하위 항목 목록을 함께 전달한다. 기존 데이터와 하위 항목의 자동 삭제·볼륨 삭제는 수행하지 않는다.

## API 계약

- 관리자 생성/수정 요청에 `items: [{ itemType, summary, displayOrder }]`를 추가한다.
- 관리자/사용자 응답에 `items`를 포함한다.
- 기존 게시 상태 변경, 삭제, 페이지네이션 엔드포인트는 유지한다.
- 버전은 `vMAJOR.MINOR.PATCH` 형식을 허용하고 같은 삭제되지 않은 릴리즈의 중복 버전은 거부한다.
- 게시되지 않은 릴리즈는 사용자 API에서 반환하지 않는다.

## 관리자 UI

- 버전 입력 옆에 형식 예시와 중복 가능성을 안내한다.
- 항목 편집기는 첫 행을 기본으로 표시하고 `항목 추가`, 행별 삭제, 위/아래 순서 버튼을 제공한다.
- 항목 유형은 한글 표시명으로 선택하고 저장 payload에는 enum을 사용한다.
- 행 단위 검증 오류를 해당 행에 표시하며, 항목이 0개면 저장하지 않는다.
- 게시 여부는 기존 토글을 유지하고, 게시 시 사용자 미리보기와 게시일 기록을 안내한다.

## 사용자 UI

- 한 카드가 한 버전이며 버전, 게시일, 릴리즈 제목을 상단에 표시한다.
- 카드 내부 항목은 `추가·개선·수정·보안·기타` 배지와 요약 목록으로 표시한다.
- 상세 페이지나 HTML 본문 편집은 추가하지 않는다.
- 페이지네이션은 항목 수가 아닌 릴리즈 수를 기준으로 유지한다.

## 오류 및 보안

- 서버에서 버전 형식·중복·항목 수·유형·요약 길이를 재검증한다.
- HTML 본문을 새 항목 요약으로 허용하지 않고 순수 텍스트로 저장·응답한다.
- 권한·게시 필터·소프트 삭제 조건은 기존 패치노트 API와 동일하게 적용한다.

## 검증 기준

- 기존 패치노트가 새 화면에서 사라지지 않는다.
- 버전 하나에 1개 이상 항목을 저장하고 수정·순서 변경·삭제할 수 있다.
- 비게시 릴리즈는 사용자 화면에 나타나지 않는다.
- 사용자 화면은 버전 단위로 페이지네이션한다.
- 백엔드 단위/웹 계층 테스트와 프론트 폼·목록 테스트, 타입체크를 통과한다.
